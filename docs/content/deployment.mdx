# Deployment (Cloudflare)

The app deploys to **Cloudflare Workers** via `@opennextjs/cloudflare`, with **D1**
for snapshots and a separate **Cron Worker** for daily capture.

Provision D1 and the required secrets before deploying. The separate docs site
uses Cloudflare Pages; the application uses Workers.

## 1. Create the D1 database

```bash
wrangler d1 create traffic_analytics
# paste the returned database_id into wrangler.jsonc and wrangler.snapshot.jsonc
wrangler d1 execute traffic_analytics --remote --file db/schema.sql
```

## 2. Build & deploy the app

Set the production URL and OAuth callback in your GitHub OAuth App:

```text
Homepage: https://github-traffic-analytics.ali-ammari.workers.dev
Callback: https://github-traffic-analytics.ali-ammari.workers.dev/api/auth/callback/github
```

Use your own Worker URL when deploying a fork. Set `NEXTAUTH_URL` to that URL,
then add `NEXTAUTH_SECRET`, `GITHUB_CLIENT_ID`, and `GITHUB_CLIENT_SECRET` as
Worker secrets with `wrangler secret put <NAME>`. `GITHUB_PUBLIC_TOKEN` and
`ANTHROPIC_API_KEY` are optional server-side secrets. Keep all secret values out
of source control.

```bash
pnpm cf:build      # opennextjs-cloudflare build
pnpm exec opennextjs-cloudflare deploy  # deploy the build above
```

## 3. Deploy the snapshot cron worker

```bash
wrangler deploy --config wrangler.snapshot.jsonc
```

It captures traffic daily at 06:00 UTC (`triggers.crons`) and checks opt-in
weekly email schedules hourly. Users must opt in to weekly email separately.
The Cron Worker uses the same D1 database. Users must opt in to tracking before
it captures their repository traffic.

### Configure weekly email

The D1 schema creates `weekly_digest_preferences`, `report_deliveries`, and
`traffic_source_snapshots` for top-referrer/path captures.
Existing deployments can apply the additive migration before deploying:

```bash
wrangler d1 execute traffic_analytics --remote --file db/migrations/0002_weekly_digest.sql
wrangler d1 execute traffic_analytics --remote --file db/migrations/0003_github_reports.sql
```

Verify a sender domain with Resend, then set these secrets on the **snapshot
Worker** (the worker that also runs digest checks):

```bash
wrangler secret put RESEND_API_KEY --config wrangler.snapshot.jsonc
wrangler secret put REPORT_FROM_EMAIL --config wrangler.snapshot.jsonc
```

`REPORT_FROM_EMAIL` must be an address on that verified domain. Once both are
configured, set `DIGEST_EMAIL_ENABLED=true` on the **application Worker** and
redeploy it. Keep the flag false until mail delivery is ready. Opt-in saves the
verified primary GitHub email, enables daily tracking for that repository, and
sends at the first hourly check in the user's Monday 09:00–09:59 local window.
The 10:00 and 11:00 checks retry failed deliveries. Every send has a D1
delivery claim and a provider idempotency key. UTC reporting windows include
only complete days, so the ending date can differ by timezone.
For a fork, also set `SITE_URL` on the snapshot Worker to your own HTTPS origin;
the default links to the production deployment shown above.

## CI deploy (gated)

`.github/workflows/deploy.yml` deploys on push to `main`, but only when the
repository variable `ENABLE_CF_DEPLOY` is `true` and these secrets are set:

| Secret                                         |                       |
| ---------------------------------------------- | --------------------- |
| `CLOUDFLARE_API_TOKEN`                         | Cloudflare API token  |
| `CLOUDFLARE_ACCOUNT_ID`                        | Cloudflare account id |
| `NEXTAUTH_SECRET`, `NEXTAUTH_URL`              | NextAuth              |
| `GH_OAUTH_CLIENT_ID`, `GH_OAUTH_CLIENT_SECRET` | GitHub OAuth          |
| `ANTHROPIC_API_KEY`                            | AI insights           |

Weekly email also needs `RESEND_API_KEY` and `REPORT_FROM_EMAIL` configured as
secrets on the snapshot Worker, plus `DIGEST_EMAIL_ENABLED=true` on the app
Worker. These are optional; without them the email opt-in stays disabled.

Without them the deploy job is skipped — forks and CI never attempt a deploy.
